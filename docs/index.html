Three ways to talk across a boundary

Every message travels over a channel bound to one known peer. Pick the shape that fits the conversation.

request()

Call a function in another context and await its result. Each call has a deadline, and the answer must come from the peer you asked.

// worker.js
bus.handle('fib', ({ n }) => fib(n));

// page.js
const value = await bus.request(
  'worker', 'fib', { n: 30 });

signal()

Notify every connected peer without waiting for an answer. Listeners get the payload and the peer it came from.

// every tab
bus.on('cart:updated', event => {
  render(event.data.payload, event.data.source);
});

await bus.signal('cart:updated', { items: 3 });

StreamManager

Move large or binary data in chunks, with bounded queues, optional consumption acknowledgements, deadlines and cancellation.

receiver.onStream('upload', s => s.collect());

const writer = sender.createStream(
  'upload', 'worker', { flowControl: true });
await writer.write(bytes);
await writer.end();

Trust boundaries you configure, not assume

CrossBus.createSecure() starts strict. What the library enforces, and what stays with your application, is written down.

CrossBus enforces

  • Exact originsMissing or wildcard allowlists are rejected. Window transports also verify the source window.
  • Channel-bound identityA response must come from the peer that was asked. allowedPeers authorizes callers by the channel they arrive on.
  • Fail-closed hooksA hook or validator that throws stops the message, so a rejected request never runs its handler.
  • Budgets by default1 MiB payloads, 100 pending requests and 30-second deadlines, plus per-handler rate limits. destroy() closes every transport.

Your application remains responsible for

  • AuthenticationUsers and the initial channel setup, such as how a MessagePort is handed over.
  • KeysGenerating and distributing keys for the encryption plugin.
  • ForwardingAuthorizing any routing between peers. isHub does not forward on its own.
  • Telling tabs apartOn BroadcastChannel all tabs share one bound peer.

These are project-maintained checks, not an independent security certification. Read the security guide and the audit record.

Load only what you use

The package has no runtime dependencies. Optional modules are separate subpaths, so a bundler leaves out what you never import.

crossbusESM + CJS

The bus, emitters, every transport, streams, presence and ordering utilities.

crossbus/core

The CrossBus class with its event API, without transports.

crossbus/nano

A minimal local event emitter.

crossbus/plugins/encryption

AES-256-GCM through Web Crypto. Key distribution is up to you.

crossbus/plugins/retry

Retries with withRetry and createRetryWrapper.

crossbus/plugins/circuit-breaker

A circuit breaker, per peer if you need it.

crossbus/plugins/rate-limiter

RateLimiter and withRateLimiter.

crossbus/plugins/compression

Payload compression with a cap on decompressed size.

crossbus/plugins/batch

Batching for senders; receivers turn on unbatching.

crossbus/plugins/schema-validation

A documented subset of JSON Schema, not a full validator.

crossbus/enterprise

Tracing, metrics, backpressure and message versioning.

crossbus/testing

MockTransport and connected mocks for tests.

When something simpler fits

CrossBus suits applications that connect several kinds of contexts and want the same origin checks, authorization, budgets and teardown everywhere. For narrower jobs these are good choices:

Comlink

Proxy-style remote objects, typically for a single worker.

birpc

Minimal function RPC over a transport you supply.

Penpal

Parent and iframe connections with a built-in handshake.

The source-reviewed comparison records design differences and measured trade-offs at exact versions.
